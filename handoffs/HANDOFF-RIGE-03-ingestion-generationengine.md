## Inference boundary

RulesIngestion continues to own:

- extraction/enrichment prompts;
- structured output schemas;
- cache keys/fingerprints;
- admissibility/gates;
- concurrency policy at the workflow layer;
- interpretation of generated enrichment.

GenerationEngine owns provider execution, credentials, provider/model resolution, retries/deadlines, usage, and failures.

Prefer one small RulesIngestion consumer adapter that can be injected/mocked instead of passing raw OpenAI clients through extraction APIs. The adapter must expose task-shaped RulesIngestion methods or a narrow generic call surface without reimplementing provider logic.

## Artifact parity gate

For each migrated ingestion family, freeze representative current fixtures before changing execution.

Prove:

```text
same source fixture
+ same prompt/schema/model target
→ same required structured meaning
→ same provenance/evidence identity
→ same Stage A/B gates
→ explicit new execution metadata
```

Exact prose generated by a model need not be byte-identical if the old API cannot guarantee that. Any difference that changes EvidenceUnit identity, corpus fingerprint, admissibility, or benchmark projection is a **stop and explicit migration decision**, not incidental drift.

Stage A′ remains retrieval-only/non-authoritative under its current contract.

## Cache/version behavior

Provider-execution ownership is part of cache identity where it can affect generated artifacts.

Do not let existing cached direct-OpenAI artifacts masquerade as fresh GE outputs. Either:

- retain them as explicitly historical cache entries; or
- version the execution contract/cache key so GE runs produce separate entries.

Document the choice.

## Credentials

After this PR, extraction code does not read `OPENAI_API_KEY` directly. Environment/bootstrap code may still make the credential available for GenerationEngine, but provider ownership belongs to GE.

## Do not

- change EvidenceUnit schema/identity rules;
- migrate OCR/DeepSeek/local extraction-model execution into GE;
- change TOC/orphan heuristics except where required to preserve prior semantics;
- change Retrieval Lab ranking/eval logic;
- broaden Stage C.

## Acceptance proof

1. No active `extraction/` module imports/constructs OpenAI SDK clients.
2. Frozen fixture parity proves no unreviewed corpus/admissibility drift.
3. Cache identity correctly separates old direct-provider execution from new GE execution.
4. Failures remain explicit and testable.
5. Full ingestion and repository test gates pass.

Acceptance token:


## Stop conditions

Stop and split if the migration changes:
- EvidenceUnit IDs;
- corpus content fingerprints;
- gate outcomes;
- table/list reconstruction;
- source provenance.

Those are substrate changes, not provider-migration details.
